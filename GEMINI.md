# Design Inspector Chrome Extension

## Project Overview
**Design Inspector** is a comprehensive Chrome Extension (Manifest V3) designed for developers and designers to analyze, extract, and replicate web design systems. It features a "God-Tier" visual inspector, automated asset/style extraction, scroll animation detection, and AI prompt generation for component recreation.

## Tech Stack
- **Frontend:** React 18, TypeScript, Tailwind CSS, Framer Motion
- **State Management:** Zustand
- **Build Tool:** Vite
- **Icons:** Lucide React
- **Backend (Optional):** Node.js (Express) with Google Gemini integration for AI prompt refinement

## Architecture

### Core Components
1.  **Popup UI (`src/popup/`)**:
    *   A React application running in the extension popup.
    *   Uses **Zustand** (`src/store/index.ts`) for global state management.
    *   Displays extracted data (Typography, Colors, Assets, etc.) in tabbed panels.

2.  **Content Scripts (`src/content-scripts/`)**:
    *   `content.ts`: Main entry point. Orchestrates data extraction and message passing.
    *   `inspector.ts`: Handles the visual inspection overlay (hover/click), measurements, and DOM interaction.
    *   `pageContext.js`: Injected script to access the window object (required for detecting libraries like `ScrollTrigger` or `__reactFiber`).
    *   **Extractors (`src/content-scripts/extractors/`)**: Modular TypeScript files for specific tasks (e.g., `fontExtractor.ts`, `scrollAnimationDetector.ts`).

3.  **Background Service Worker (`src/background/`)**:
    *   Handles screenshot capture (`chrome.tabs.captureVisibleTab`).
    *   Proxies requests to the optional local backend to avoid CORS issues.

### Data Flow
1.  **Extraction:** When the popup opens, it sends a message to `content.ts`.
2.  **Processing:** `content.ts` runs various extractors. It may inject `pageContext.js` to get runtime data (like animations) via `window.postMessage`.
3.  **State Update:** Aggregated data is sent back to the popup and stored in the Zustand store.
4.  **Interaction:** The "Inspector Mode" allows users to hover/click elements on the page. This is managed by `inspector.ts` which overlays visual guides directly on the DOM.

## Development

### Setup & Build
*   **Install Dependencies:** `npm install`
*   **Dev Server:** `npm run dev` (Starts Vite with hot reload)
*   **Production Build:** `npm run build` (Outputs to `dist/`)
*   **Preview:** `npm run preview`

### Loading the Extension
1.  Open Chrome and navigate to `chrome://extensions`.
2.  Enable **Developer mode** (top right).
3.  Click **Load unpacked**.
4.  Select the `dist` directory generated by `npm run build`.

### Backend (Optional)
The backend service enhances AI prompt generation.
*   **Location:** `backend/`
*   **Start:** `cd backend && node server.cjs`

## Key Conventions

### Code Style
*   **TypeScript:** Strict typing is enforced. Interfaces for all data structures (e.g., `InspectionData`, `FontData`) are defined in `src/store/index.ts`.
*   **Styling:** Tailwind CSS is used for all UI components.
*   **Components:** Functional React components with hooks.

### State Management (Zustand)
*   **Store:** `src/store/index.ts`
*   **Pattern:** Logic for updating state (e.g., `setInspecting`, `setData`) is contained within the store actions.
*   **Reset:** The `reset` action clears session data but preserves user preferences.

### Extractor Pattern
New analysis features should be implemented as separate extractors:
1.  Create `src/content-scripts/extractors/myNewExtractor.ts`.
2.  Export a function that returns typed data.
3.  Integrate into `content.ts`.
4.  Update `InspectionData` interface in `src/store/index.ts`.

## File Structure Highlights
*   `vite.config.ts`: Custom configuration to handle multi-entry points and copy `pageContext.js`.
*   `src/content-scripts/inspector.ts`: Logic for the visual overlay, identifying elements, and calculating computed styles.
*   `src/popup/App.tsx`: Main UI entry point, handling tab navigation.
